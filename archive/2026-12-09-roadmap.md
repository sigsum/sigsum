# 2026-12-09

This document provides an overview of Sigsum's roadmap and people with standing
responsibilities.  A new roadmap will be decided in March, 2026.

## High-level priorities

In roughly this order whenever possible:

  1. Specification work
  2. Sigsum logs are operated with good business continuity
  3. Witnesses are operated with good business continuity
  4. It is easy to use Sigsum
     - Wrt. integrating into something existing
     - Wrt. being a party that offline-verifies
     - Wrt. being a party that monitors
  5. Further development (broader and possibly experimental)

From these high-level priorities we define shorter-term activities.

## What happens after March, 2026

To be decided, but we don't expect any major changes in high-level priorities.
Much of 2027 is expected to be about sigsum/v2 and improving the witness story.

A natural next TKey app after sign-if-logged is a log signer app for v2.  We
have yet to decide if we will do this, but it is something we're considering.

Another likely roadmap candidate is to start using Sigsum for our releases.

For further hints on what might be selected as the main activities in the
future, refer to Sigsum's [issue boards][] and (sometimes "DRAFT:")
[milestones][].  Try filtering on the GitLab ["Future" tag][].  If you have
input on what you want to see work on, file and comment on issues or reach out
as you see fit.  Contact information can be found on <https://www.sigsum.org/>.

## Summary of progress since August, 2026

  - Several contributors attended the [transparency.dev summit][tds].
    A few highlights:
    - [Setting thresholds in witness cosigning][tds-lucia]
    - [Archive Transparency][tds-tta] (lightning talk by tta)
    - [tlog-addenda: an adoptable standard for log-adjacent data, mirroring, and redaction too][tds-warpfork] (lightning talk by warpfork)
    - [The diff between sigsum/v1 and sigsum/v2?][tds-rgdd] (lightning talk by rgdd)
    - [The sign-if-logged tool][tds-nisse] (full talk by nisse)
    - Transparency.dev transitions to [shared governance in SPI][tds-spi].  The
      initial technical steering committee members are rgdd, filippo, and Al
      Cutter.  Since the summit's announcement, Andrew Ayer and Mari Galicer
      have also joined the technical steering committee.  To keep an eye on
      this, join [tsc@lists.transparency.dev][].
  - Several contributors attended [Tor gathering][tcg], a highlight:
    - Session on Tor consensus transparency, see [notes][tcg-ctrans].
  - Several contributors attended the [reproducible builds summit][rbs], a highlight:
    - Talk to Arch Linux folks about the overlap between transparency and
      [Signstar](https://gitlab.archlinux.org/archlinux/signstar).
  - Stable version of the sigsum-go library is available, [v1.0.0][sigsum-go-v1].
    - Intent: was our last chance to dub a stable library version before
      simultaneously starting to work on what will eventually be v2.0.0.
  - New release of sigsum-rs, [v0.4.0][sigsum-rs-4].
    - TODO(@gregoire): any notable changes to mention here?
  - New releases of log-go, versions [v0.16.0][log-go-16]--[v0.17.0][log-go-17].
    - Notably includes refactored and improved Prometheus metrics as well as
      support for presenting mTLS certificates when requesting cosignatures.
  - TODO(@quite): New release of sigsum-agent, version [v0.X.Y][sigsum-agent-v].
    - Notably includes support for multiple YubiHSMs (parallel signing) as well
      as soft ML-DSA-44 keys.
  - New release of litewitness, see torchwood [v0.10.0][torchwood-10].
    - Notably includes support for logs that sign checkpoints with ML-DSA-44.
  - A fork of litewitness is also available that supports ML-DSA-44 witness keys
    as well as using multiple keys.  Tested with the above sigsum-agent release.
    - TODO(@quite): In the process of being upstreamed, see [PR][torchwood-pr].
  - Sigsum's ansible has a new tag, [v0.18.0-dev.0][ansible-v18].
    - Notably masks otherwise breaking config changes in [litewitness
      v0.10.0][torchwood-10] (only relevant for global bastion users).
  - New C2SP.org `tlog-*` releases that support ML-DSA-44.
    - <https://c2sp.org/tlog-witness@v1.1.0>
    - <https://c2sp.org/tlog-cosignature@v1.1.0>
    - <https://c2sp.org/tlog-checkpoint@v1.1.0>
  - New C2SP.org specification in the `tlog-*` family: [tlog-list][].
    - It's the same format which is also defined by witness-network.org.  We
      expect witness-network.org to eventually point at [tlog-list][] instead.
  - Work in progress [sigsum/v2 specification][sigsum/v2] is available.
    - Intent: use as much of the C2SP.org specifications as possible, with one
      of the bigger open questions being the [identity-based leaf
      specification][leaf-spec].  For more context on this, see
      [rgdd's][tds-rgdd] and [hayden's][tds-hayden] [transparency.dev
      summit][tds] talks.
    - As an intermediate step towards sigsum/v2, we are implementing
      [sigsum/v1.1][].  The main feature is to support ML-DSA-44 cosignatures.
    - Follow sigsum weekly meets and proposals to follow our iterations here.
  - Work in progress sigsum/v2 implementation is available.
    - Source: https://git.glasklar.is/nisse/prototype-sigsum-v2
    - Server: http://poc-v2.test.sigsum.org:2001/
  - Glasklar's high-availability witnessing infra is in production, more info:
    - https://git.glasklar.is/glasklar/services/witnessing/-/blob/main/g1.witness.glasklar.is/about.md
